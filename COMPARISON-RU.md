## Сравнение `store2` и MobX

Обе библиотеки решают одну задачу — реактивное управление состоянием. Они вдохновлены одними и теми же принципами, но реализуют их по-разному.

---

### Сходства

- **Реактивные примитивы**:  
  В обеих библиотеках есть понятие реактивного значения (в MobX — `observable.box`, в store2 — `Atom`), вычисляемых значений (`computed`), реакций (`autorun`, `reaction`, `when`).

- **Пакетная обработка изменений**:  
  `batch` в store2 и `action` / `runInAction` в MobX позволяют группировать изменения, чтобы уведомления приходили только один раз.

- **Наблюдаемые объекты и классы**:  
  Обе библиотеки предоставляют возможность делать существующие объекты и классы реактивными через `makeObservable` и `makeAutoObservable`.

- **Отписки и жизненный цикл**:  
  Подписки можно отменять с помощью возвращаемых функций или `AbortSignal`. Есть методы `onHasSubscribers` / `onNoSubscribers` для управления ресурсами.

- **Асинхронность**:  
  Обе библиотеки поддерживают работу с промисами, хотя подходы разные.

---

### Отличия

| Аспект                     | MobX                                                                                                                                         | store2                                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Основной подход**        | **Прозрачная реактивность** – любой объект/класс можно сделать наблюдаемым, изменения отслеживаются автоматически через прокси и декораторы. | **Явные реактивные контейнеры** – пользователь создаёт `Atom`, `Computed`, `Collection`, `Store` и т.д. Реактивность возникает только через них.         |
| **Глубокая реактивность**  | По умолчанию реактивны все свойства объекта на всех уровнях вложенности.                                                                     | Требует явного указания: `ShallowReactive` только для верхнего уровня, для вложенных объектов нужно повторять обёртку или использовать `makeObservable`. |
| **Работа с массивами**     | `observable.array` предоставляет привычный массив со всеми методами (push, pop, splice).                                                     | Два подхода: `Collection` (прокси-массив, похож на MobX) и `ReactiveList` (список с методами add/setItem/remove, ориентированный на объекты).            |
| **Интеграция с React**     | Официальный пакет `mobx-react` предоставляет хук `useObserver`, HOC `observer`, готовые решения.                                             | Нет готовой интеграции; можно использовать самостоятельно через `useEffect` и `subscribe`.                                                               |
| **Декораторы**             | Поддерживаются (классический синтаксис `@observable`, `@computed`, `@action`).                                                               | Не поддерживаются, используется только `makeObservable` / `makeAutoObservable`.                                                                          |
| **Инструменты разработки** | MobX DevTools (расширение для браузера) с визуализацией графа зависимостей, отладкой действий, трассировкой.                                 | Нет DevTools; только ручное логирование.                                                                                                                 |
| **Асинхронность**          | `flow` — генераторы для асинхронных действий с автоматической отменой.                                                                       | `fromPromise` — обёртка над промисом с реактивными состояниями; асинхронные действия нужно реализовывать вручную через `async/await` и `runInAction`.    |
| **Строгий режим**          | Возможность включить `enforceActions: "always"`, запрещающий мутации вне действий.                                                           | Только блокировка мутаций во время уведомлений (`subscribersMode`); глобального запрета нет.                                                             |
| **Размер**                 | ~15 КБ (минифицированный) плюс зависимости для React-интеграции.                                                                             | ~10 КБ + только одна зависимость (`@supercat1337/event-emitter`).                                                                                        |
| **Зависимости**            | Нет внешних зависимостей (кроме опциональных для React).                                                                                     | Есть одна зависимость (event-emitter).                                                                                                                   |
| **Зрелость и экосистема**  | Стабильная, широко распространена, множество примеров, плагинов, интеграций.                                                                 | Молодая библиотека, экосистема только формируется.                                                                                                       |

---

### Когда выбирать MobX

- Если вам нужна **глубокая реактивность** «из коробки».
- Если проект уже использует React и вы хотите готовую интеграцию.
- Если вы привыкли к декораторам и «магии» MobX.
- Если требуется мощная отладка, DevTools и строгий контроль.
- Если вы работаете над крупным проектом с большим количеством взаимосвязей.

---

### Когда выбирать store2

- Если вы предпочитаете **явные структуры данных** и хотите контролировать, что именно является реактивным.
- Если вам нужна лёгкая библиотека без лишних зависимостей и минимальным размером.
- Если вы работаете в среде, где React-интеграция не требуется (Vanilla JS, Node.js, другие фреймворки).
- Если вам важна простота и предсказуемость, а не «магия».
- Если вы создаёте библиотеку или плагин и не хотите тащить тяжёлые зависимости.

---

### Вывод

`store2` — это **лёгкая альтернатива MobX**, которая сохраняет основные принципы реактивности, но делает их более явными и контролируемыми. Он подходит для 80% задач, где нужна реактивность без избыточной сложности. MobX остаётся лучшим выбором для сложных корпоративных приложений и проектов с глубокими связями, где важны отладка и масштабируемость.

В конечном счёте выбор зависит от ваших предпочтений и требований проекта. Если вам нужна сила и гибкость — выбирайте MobX. Если вы ищете лёгкость, простоту и контроль — store2 отличный вариант.
